# OI 题目重构、强数据、题解与双包交付 Skill（V3.8 修订版）

> 修订重点：题意自足、拆分编号；暴力仅能拿部分分时必须讲透并给代码，暴力已满分时不强凑部分分；代码保持简单；实际采用的搜索与 DP 画状态简图。
> 核心目标：**不改变原题难度；先设计部分分与错误模型，再造数据；代码采用常见、直观的写法；题解清楚；单题文件同级存放；完整包与选手包严格隔离。**

---

## 0. 适用范围、任务模式与优先级

### 0.1 适用范围

默认处理静态、非交互、使用标准输出比较的 OI / OJ 题目。

若题目必须使用 SPJ、checker 或交互器，而用户又要求严格精简目录，则标记 `BLOCKED_SPECIAL_JUDGE`，不得删除必要判题组件后声称可直接评测。用户明确允许例外时，才在完整包对应 `T?/` 根目录加入必要判题文件；选手包仍不得包含它们。

设本次实际题目数量为 `K`。目录使用 `T1` 至 `TK`，不强制必须恰好四题。四题时自然为 `T1`～`T4`；两题时只生成 `T1`、`T2`。

### 0.2 任务模式

- `AUDIT_ONLY`：只审查并给出问题，不改文件、不生成题包。
- `REPAIR_EXISTING`：只修复用户指定范围；不得强制重做无关文件。
- `RECONSTRUCT_INCOMPLETE`：补齐缺失题面、代码、数据、题解和公开材料。
- `BUILD_COMPLETE_PACKAGE`：完成整套题并生成双包。
- `DESIGN_NEW_PROBLEM`：用户明确要求原创时使用。
- `SKILL_REVIEW`：只审查或修改本 Skill。

只有 `RECONSTRUCT_INCOMPLETE`、`BUILD_COMPLETE_PACKAGE`，以及用户明确要求完整交付时，才执行完整双包流程。窄范围请求服从窄范围，不得为了“流程完整”擅自重做整套题。

### 0.3 冲突处理顺序

事实来源优先级：

1. 用户当前明确指令；
2. 原始正式题面或可核对的题面图片；
3. 原题解、std、评分配置；
4. 样例与现有数据；
5. 合理但保守的推断。

材料互相冲突时，不得静默选一个版本；内部记录冲突与处理依据。影响题意、评分或正确性的必要问题只在对话中简要说明并按需确认，不写入题解；一般核对、补全和重构过程不对外罗列。无法唯一确定核心语义时标记 `BLOCKED`。

### 0.4 质量优先级

> 原题题意与难度不变 > 正确性 > 评分公平 > std 稳定通过 > 代码常见、简单可讲 > 强数据与杀错 > 题解清楚 > 文件与版式。

不得为了赶进度虚假声明 `PASS`。

### 0.5 本 Skill 修订自检

每次修订都检查全文相关章节是否冲突，尤其是“必须/可选”、代码交付、图和验收规则；删除重复、过时或无用的句子。用尽量少的话写清触发条件、具体动作和验收标准；未解决的冲突明确标出。

## 1. 难度锁定与重构边界

除非用户明确授权，不得：

- 扩大主要参数、值域、总规模、查询数或操作数；
- 增加新参数、新操作、新约束维度；
- 将静态改动态、单次改大规模多次、序列改图树；
- 缩紧时限以淘汰原本合理的算法；
- 把 T1/T2/T3 人为升级为更后位置的难度；
- 修改答案定义或合法输入集合。

允许：

- 修正歧义、错字、公式、格式和样例；
- 在原总约束内重造测试点、重划自然子任务；
- 补齐缺失题面、代码、题解、样例、附件和数据；
- 采用与原预期算法等价或更简单的正确满分算法。

若发现一个对全部合法输入都正确、且更简单的满分算法，它属于合法满分解法。不得通过加强数据或修改题意把它“卡掉”；应据此重新评价题目实际难度。

### 1.1 每题内部难度基线

造数据前记录：

| 项目 | 内容 |
|---|---|
| 题目位置 | T? |
| 原题意与总约束 | 主要变量、值域、总规模 |
| 原子任务 | 分值、范围、特殊性质、累计或独立 |
| 原预期算法 | 思路、时间、空间、指定教学方法 |
| 原知识点与难度 | 需要掌握什么 |
| 参数角色 | 各参数语义、是否可交换 |
| 关键边界 | 首尾、闭开区间、阈值、无解等 |

重构结束时重新比较题意、约束、算法门槛、知识点和套题位置。未经授权变难时必须回退。

## 2. 统一执行流程

完整重构按以下顺序执行；只执行与当前任务模式有关的步骤：

1. 清点材料，确认题意、约束、子任务和缺失项。
2. 建立难度基线，锁定不允许变化的内容。
3. 按题意拆分子问题，先用最直接的方法组成完整算法；计算各步调用次数与单次代价，代入范围判断是否够用。不足时定位瓶颈并改进，够用则直接作为满分候选。DP、递归和码风分别按第 7.5、3.4、3.5 节。
4. 核对原公开子任务；依据最直接做法及其优化分析自然部分分，确定映射和对应代码，不为题解形式人为造档。题解讲解顺序按第 7 节，不影响“分档和错误模型先于正式造数据”。
5. 建立参数角色、复杂度退化、枚举边界和题目特有错误模型。
6. 编写最终 `std.cpp`、各档参考代码及内部暴力/独立实现、变异程序；部分分源码仅作内部验证，不单独交付。
7. 先建立“测试点—部分分—错误模型”映射，再生成正式数据。
8. 编译、对拍、性能、递归深度、实际得分和杀错验证；不达标则修复，不擅自改变既定约束。
9. 按第 7 节生成单题与汇总题解：自足的简化题意、编号的问题拆分、逐步分析的部分分与满分做法、完整参考代码和知识点总结。实际采用的搜索及 DP 按第 7.5 节画图。普通样例写入题面，公开附件经验证后打包。
10. 按第 8 节组装完整包：保留 `data/` 并生成 `data.zip`；公开附件只交付 `attachment.zip`，不复制其内部工作目录；再按公开白名单复制生成选手包。
11. 检查白名单、单题与整套题解一致性、样例与附件合法性、内层 ZIP 内容、双包哈希、全部 ZIP 完整性及 PDF 版式。

禁止先造数据再倒推部分分、错误模型和题解。

## 3. 满分算法与最终代码

### 3.1 满分解法数量

每题保留 1～3 种真正不同的满分解法，**默认只保留 1 种**。只有第二、第三种解法同时满足以下条件时才加入：

- 核心观察、状态设计、数学推导或数据结构确实不同；
- 能通过完整数据；
- 具有明显教学价值；
- 代码仍然清楚，不是为了凑数量或展示技巧。

滚动数组、换循环方向、换容器、改变量名，以及仅将递归改为显式栈，不算新解法。

`T?/std.cpp` 对应推荐主解法：用户已指定课堂训练方法时优先落实该方法；否则在正确、能稳定通过的候选中，优先选择竞赛教学中的常见做法和学生容易直接写出的实现，再比较状态、数组与代码结构是否简洁。不能只为减少一两个状态、避免递归或追求微小常数而改成陌生写法。其他合法满分算法仍应接受。

### 3.2 最简实现原则

正确性和可靠通过优先于“表面简单”。在此基础上：

- 优先直接递归、普通循环、常见 DP 和基础 STL 等贴近题意的实现，不为统一框架而模拟执行过程；
- 只保留算法真正需要的状态、数组、容器和函数；
- 完整 DP 表清楚且内存足够时，不做非必要滚动或压缩；
- 已知容量上界且内存足够时优先普通数组。确需 `vector` 时，已知长度就直接构造，如 `vector<int> v(n + 1);` 或 `vector<int> v(1e5 + 10);`；不要无理由先建空容器再 `resize`。只有大小后续确会变化时才使用 `resize` 或 `push_back`；
- 普通数组足够时，不用 `map`、`set`、哈希或多层容器；
- 普通 `cin/cout` 足够时，不写自定义快读；
- 不为少量复用建立类、框架、函数指针或复杂表驱动；
- 不为让 `main()` 很短而拆出大量只调用一次的小函数；
- 允许少量直观重复代码换取可读性；
- 题面使用 1 下标时，代码优先使用 1 下标；
- 每个状态和辅助函数都必须能用一句话说明必要性。

定稿前逐个检查动态容器、辅助函数和复杂语法是否必要，能用普通数组与循环写清的就简化；任何改动后重新编译、对拍、跑正式数据和性能测试。

### 3.3 最终参考代码语法

最终 `std.cpp`、单题及整套 `solution.md` 中的全部满分/部分分参考代码统一使用基础 C++14，并按第 3.5 节采用用户提供的代码样例风格；不能只修改独立源码而遗漏题解代码。

默认禁止：

- lambda、递归 lambda；
- `std::function`、`std::bind`；
- `auto`、`decltype`、结构化绑定；
- 自定义复杂模板、PBDS、ranges；
- `#define int long long`、`signed main()`、复杂宏；
- 匿名比较器、嵌套三目、逗号运算符、链式状态修改；
- 为缩短代码使用的复杂 STL 一行式、位技巧或隐式编码。

递归和比较器使用命名函数；变量类型显式；核心转移分步写成普通循环和 `if`。允许确有必要的基础 STL，如 `vector`、`queue`、`priority_queue`、`sort`、`lower_bound`。

代码扫描只检查代码本身，排除注释和字符串误报。

### 3.4 常见做法与递归优先

适用于 std、全部满分/部分分参考代码和整套题解：

- 树的 DFS、子树统计、树形 DP、分治和回溯，递归能直接表达题意时，默认使用普通命名递归函数。不主动改为“先记录遍历序再逆序处理”、进出栈标记或手工调用帧来模拟递归。
- **只有题目或用户明确强调空间／调用栈限制，且确实需要针对该限制处理，或用户直接要求非递归时，才使用显式栈模拟递归。** 每题正常写一行空间复杂度，不构成采用显式栈的授权；不能为了满足条件自行增写一个“空间优化”栏目。
- 例如《特殊的中序遍历》的主解应直接递归处理儿子，再用 `swap` 接管重儿子的 vector、追加根与轻儿子序列；不要仅为实现偏好换成栈模拟。
- 单调栈、括号匹配、表达式求值等本身就以栈为算法核心的做法，以及 BFS 的队列，不属于“栈模拟递归”，仍可正常使用。
- 递归必须验证题面允许的最大深度、实际栈限制和长链等输入。普通递归与保存调用帧的显式栈通常都占 O(h) 辅助空间，h 为递归深度；不得把改用显式栈直接宣称为空间复杂度下降。
- 若递归存在未验证的栈风险，标记 `RISK`；已复现崩溃则标记 `NEEDS_FIX`。先向用户说明并确认评测栈环境，或请求允许采用非递归；不得擅自换成栈模拟，也不得通过删除深链、降低范围、未经确认增大栈限制来伪造通过。
- 内部独立验证程序可以使用非递归，但它的通过不能替代最终递归 std 的实际验证。必要风险仅在对话中简要说明，不把部署与重构过程写入题解。
- **按依赖顺序循环填 DP 表不属于“显式栈模拟递归”。** 先从搜索讲清递推，再采用自然的记忆化搜索或循环递推；不因“搜索先行”强制最终 std 使用递归，也不因此授权将树 DFS 改写成手工调用栈。

### 3.5 直接采用用户提供的代码样例风格

本节依据用户提供的 DFS、结构体排序、前缀和、差分、二分与双指针代码。它替代旧版的外部作者采样流程：**不再等待外部源码、不要求确认作者或年份，也不把这些样例归为未经确认的他人作品。** 样例是写法依据，不是所有程序正确性的证明。

统一采用下列约定；样例本身有空格或缩进差异时按本表规范化，不复制粘贴产生的格式噪声。

| 项目 | 默认写法 |
|---|---|
| 头文件与入口 | `#include<bits/stdc++.h>`、`using namespace std;`、`int main()`、`return 0;`。 |
| 容量与存储 | 已知上界优先 `const int N = 1e5 + 10;` 和全局普通数组；确需动态数组时一次构造 `vector<int> v(n + 1);`，不先声明空 `vector` 再 `resize`。N 按实际范围确定。 |
| 命名 | 使用短而稳定的 `n,m,k`、`i,j`、`x,y`、`a,b`、`l,r,mid`、`pre,sum,ans`、`vis,dep,init,goal` 等；在解析或少量注释中说明含义。一个名字不同时承担无关含义，不为改短而遮蔽变量。 |
| 编号 | 物品和节点通常从 1 开始；`vector` 元素从 0 遍历，前缀和的 `b[0]` 等边界正常保留。 |
| 递归与比较器 | 普通命名函数，如 `void dfs(int x,int fa){`、`bool cmp(node x,node y){`；小记录用 `struct node{ ... };`，不套 class 或通用框架。 |
| 缩进与空行 | 每级用一个真实 Tab，展示宽度为 4 空格；工具只能输出空格时统一 4 空格，不混用。逻辑块之间至多一空行。 |
| 括号与花括号 | `for(...){`、`if(...){`、`while(...){`、`}else{`；左花括号同行，右花括号对齐。 |
| 空格 | 二元运算符两侧留空格，如 `a[i] = b[i - 1] + x;`；参数和连续声明的逗号后不留空格，如 `dfs(j,ji,ou);`、`int n,m;`；`for` 分号后留一空格。 |
| 循环与简短判断 | `for(int i = 1; i <= n; i++){`；允许 `if(vis[j]) continue;` 等单句判断。多语句、嵌套容易歧义或复杂转移使用花括号，不压成一行。 |
| 输入输出 | 默认 `cin/cout`；少量输出可用 `endl`，大量输出用 `'\n'`，必要时关闭同步，不为模仿格式牺牲性能。 |
| 算法接口 | 保留 `sort(a + 1,a + n + 1,cmp);` 等基础 STL。二分教学可用 `l,r,mid,ans` 的显式循环，普通调用 `lower_bound` 也允许；不机械展开所有库函数。 |
| 注释 | 只说明数组含义、关键条件、转移和边界，不逐行翻译语句；不用长篇注释弥补复杂实现。 |

**安全与清理属于本项目的必要规范化，不冒称为样例已满足的性质：**

- 清理 `\#`、`\<`、`&#x9;`、`&#x20;`、`push\_back` 和错乱代码围栏等粘贴残留；成品代码应是正常 C++，不是转义后的展示文本。
- 不复制重复程序、调试输出、无用数组、未使用变量或大段空白；不为保留样例外形而引入同名局部变量遮蔽全局变量。
- 数值类型、数组大小、偏移量和初始化按本题确定。需要时用 `long long`；无解时答案必须已初始化，移动指针后必须确认合法再访问，不能照搬可能越界或漏初始化的片段。
- 普通 `int` 下标访问 vector 时，可写 `for(int i = 0; i < (int)v[x].size(); i++){`，前提是容量范围确在 int 内；这种安全类型适配不算复杂语法。
- 第 3.3 节的禁用语法继续有效。样例中的“简单、直接”是目标，不要求逐字符复制不统一的空格，也不要求所有题都使用同一份模板。
- 主解代码与 `std.cpp` 原样一致；其他满分/部分分代码采用同一码风，抽取后重新编译、对拍与性能验证。

## 4. 部分分设计

### 4.1 原题已有子任务

优先保留原题公开的分档、累计关系和特殊性质。若原题为 `20% / 70% / 100%`，须逐档解释覆盖算法；有 70 分中间算法时不能只给 20 分暴力和满分法。

原子任务矛盾或无法按 10/20 点制表示时，不得静默改分；应说明冲突并采用用户授权的方案。

### 4.2 原题没有子任务

至少分析：

- 直接暴力或枚举；
- 比满分慢一档但正确的中间算法；
- 小参数、小值域、小总和；
- 自然特殊结构或数学特殊族；
- 满分算法。

只采用有真实算法意义、输入可识别、对整个子域始终正确的分档。找不到自然中间档时可以少分档，不得制造怪异性质。最直接的做法若已能通过全部数据，就将其作为满分候选；不因名字叫“暴力”就判定只能部分分，也不强行制造优化层次。原有公开分档仍须保留与解释，不能据此静默删改评分。

### 4.3 部分分代码与内部验证

先把最直接的正确算法代入完整约束：若它已能满分，就在满分 H2 讲解，不强设部分分；若它只能通过原公开的部分档，**必须**在部分分 H2 讲解其编号步骤、每步算法与成本、总时空，并附完整可编译代码。不得因为优化后的满分程序也能通过这些档，就省略暴力部分分。部分分代码只放在 `solution.md`，内部抽取编译并实测得分，不单独交付 `some.cpp`。

原公开档次逐档说明由哪种算法覆盖。多个档共用一种部分分程序时合在同一 H2、代码只贴一次；确实没有可用的非满分直接做法的档，可在满分 H2 说明。不得设无代码的部分分 H2，也不得只写“枚举”“搜索”或总复杂度。

规模型部分分应由复杂度自然失败；不得以“超过阈值就固定输出错误值”冒充部分分。特殊性质分支必须是输入可判断且对该类输入始终正确。

程序必须对声明子域始终正确。若低效解意外高分，核查实际循环次数与耗时；数据未触及最坏结构时，在原约束和分档内补强并重测。若算法在完整上界仍可通过，就按满分算法评价，不故意改错程序。确无自然非满分算法时内部标记 `NO_NATURAL_PARTIAL`，对话中说明，不制造怪异子任务或空的部分分占位文件。

### 4.4 内部部分分表

| 档次 | 分值性质 | 范围/特殊性质 | 编号步骤与各步成本 | 总时空 | 代码位置 | 计划测试点 | 超范围失败点 |
|---|---|---|---|---|---|---|---|

分值可以是累计或独立，必须明确。每档都要映射到正式测试点。

## 5. 正式测试数据与错误模型

### 5.1 基本规则

默认采用：

- 10 个测试点，每点 10 分；或
- 20 个测试点，每点 5 分。

若原公开评分无法精确映射，先报告冲突，不得擅自改写。每点为 `i.in` 和 `i.out`，放入本题 `data/`；另在本题根目录生成 `data.zip`，内部直接放这些文件，规则见第 8 节。目录统一命名为 `data`，不使用 `date`。

每个测试点必须有明确职责，可同时承担多项：部分分得分、阈值、边界、参数区分、错误反例、性能或一般覆盖。

纯随机测试点不得超过总点数的 20%。其余点必须是手工、参数化、边界、反剪枝或带后置断言的结构化随机。不得用同一生成器只换种子冒充不同覆盖。

### 5.2 三类强制错误模型

每题都判断以下错误是否适用；适用则编写安全变异程序并用正式数据实际卡掉，不适用则简要说明理由。

#### A. 参数角色错位

适用于语义不同且不可交换的参数，如 `n,m`、行列、点边、物品数与容量。

- 使用明显不对称的数据；不能只令两参数相差 1；
- 若两个方向都合法且有意义，至少覆盖“一小一大”和“一大一小”；
- 必须实际确认交换/误用变异与正确答案不同；
- 若题目本身对称，标记 `N/A（等价）`，不得硬卡。

#### B. 复杂度退化与特判逃逸

分析一个自然慢一阶正确算法及学生常见的早停、剪枝、全相等/单调/零答案特判版本。

- 设计接近最大规模且破坏特判、早停和剪枝的结构化数据；
- 用关键操作次数、至少两个规模的增长趋势或重复计时证明区分；
- 不设统一的 `1/16`、`1/3`、`1.5 倍` 等硬阈值，以目标评测环境的稳定证据为准；
- 不得通过扩大约束或故意压紧时限制造区分；
- 若原约束确实无法稳定区分，应如实报告该慢算法可能满分，重新评价题目，而不是虚假声称已卡掉。

#### C. 枚举与区间边界

列出适用边界：首尾元素、`L/R`、`<`/`<=`、`r-l+1`、0/1 下标、空前缀、单元素、无解/刚好有解、二分相邻端点。

正式数据必须让边界真实影响答案，而不是只让边界值出现在输入中。至少覆盖：

- 一个最小明确反例；
- 一个首端或下界决定答案的点；
- 一个末端或上界决定答案的点；
- 适用时覆盖阈值相邻值；
- 必要时把边界反例嵌入大规模数据，防止小规模特判。

### 5.3 其他常见错误

按题型补充：`int` 溢出、漏取模、重复元素、排序方向、状态初始化/清空、非法贪心、图的重边自环、递归深度等。

### 5.4 杀错验收

- 所有适用且非等价的三类强制变异必须被正式数据卡掉；
- 高风险错误尽量由两个结构不同的点卡掉，但不设僵硬配额；
- “卡掉”必须有实际 WA/TLE/RE/MLE/CE 结果；
- 等价变异从统计中排除并说明理由；
- 未被卡掉的非等价高风险错误使状态为 `NEEDS_FIX`。

### 5.5 正确性与合法性

- 所有输入通过约束和结构检查；
- 正式输出不能只由未经验证的 std 自证；至少与暴力、独立实现、数学公式或可靠 checker 中的一种交叉确认；
- std、其他满分解、从题解抽取的部分分程序和目标变异均应跑全部正式点；
- 内部记录每份部分分程序的实际得分和每个关键变异的首个失败点；不因取消独立源码文件而省略验证。

## 6. 样例、附件与题面

每题提供 `statement.md` 与 A4 `statement.pdf`，内容一致，并满足：

- 至少 1 组普通样例，输入、输出及必要解释直接写在题面中；不交付 `sample/` 或单独样例文件。内部从最终题面抽取样例并运行核对。
- 默认 1～3 组公开附件大样例及输出，只交付 `attachment.zip`；压缩包根目录直接为 `attachment1.in`、`attachment1.out` 等，不交付外层 `attachment/` 目录。
- 附件在内部临时目录中生成和验证后打包；最终检查 ZIP 内解压后的实际输入输出，不仅检查 ZIP 是否可打开。题面引用附件时指向同级 `attachment.zip`，不得留下旧目录链接。

普通样例解释题意，公开附件用于较大规模核对，正式数据用于计分。三类输入不得重复或仅作无意义改序/空白修改；正式数据在 `data/` 与 `data.zip` 中的镜像、两个包中的同一份公开材料不算跨类别重复。

题面必须明确输入输出、范围、下标、区间端点、重复/负数/零、无解、取模、判题方式、时间和空间限制；PDF 逐页渲染检查。

## 7. 单题题解与整套题解

适用于各题 `T?/solution.md` 和完整包根目录的 `solution.md`、`solution.pdf`。**少说过程性套话，讲清“要求什么、拆成什么、各步怎么做、代码怎么写、下次如何识别”。** 每题仅有这一份统一题解，不恢复分拆文件。

### 7.1 题解的五步顺序

1. **题号与题名。** H1 写本套题号和题名；有可核对的 OJ 题号才补充，不编造来源。
2. **简化题意。** 删故事，不删问题。独立写清输入对象及结构与规模、各参数含义、允许的操作或选择、关键合法条件、求什么和输出什么。矩阵必须说明几行几列、元素含义和可操作范围；图/树说明点边含义。保留严格/非严格、能否重排、恰好/至多、非空等影响答案的条件。读者只看此段应能复述问题，不必回看正式题面。
3. **按题意拆问题。** 必须写成 `1.`、`2.`、`3.` 等编号步骤，通常 1～4 步。每步说清要解决什么、得到什么、下一步如何使用；不把读入、声明变量或输出当作子问题。例：`1.` 选出切点并得到各段；`2.` 对每种分段枚举拼接结果；`3.` 对结果去重计数。
4. **先搭最直接方案，再算够不够。** 沿用上述编号，为每步选最简单的正确算法或数据结构，写出调用次数、单次代价及空间，再合成总复杂度并代入上界。够用则直接作为满分做法；不够时按第 4.3 节讲解可得分的直接算法，再定位瓶颈并优化。
5. **知识点总结。** 最后用少量短句提炼“问题特征 + 使用前提 → 对应方法”，不重复解题过程，不仅罗列算法名字。

第 4 步不套固定栏目。原分档、计分含义不因叙述顺序改变；实际采用的每种部分分都要逐步解释并给完整代码，同一实现覆盖多档时按第 4.3 节合并。

### 7.2 从子问题到程序，再到复杂度

**逐步落实。** 最直接做法、各部分分及满分做法沿用“问题拆分”的编号；步骤改变时重新编号并说明对应关系。每步写明算法或数据结构、处理对象、产物、调用次数 × 单次代价及额外空间；未改变的步骤可简短引用。搜索要说清参数、分支与合法叶子，并按第 7.5 节画图。可用编号列表或小表，不重复叙述。

**然后把总账算清。**

- 并列阶段的耗时相加；嵌套调用按“外层方案数 × 每个方案的后续代价”累计。只在合法叶子才执行的后续过程，不无条件乘上全部无效分支；若用粗上界，明确它是上界。
- 区分候选数量、合法方案数、不同结果数。参数关系能明显收紧估计时，使用组合数等真实计数；不能只把每层都写成最大的 `2^n`，然后据此断言必须优化。
- 数据结构复杂度使用该结构的实际规模。`set/map` 的对数取决于元素数量 M，不一定是原输入长度 n；字符串比较、拼接、复制、哈希等还要计入字符处理成本。不得机械写 `set<string>` 单次插入为 `O(log n)`。
- 给出总时间和空间，再代入题目最大范围判断；必要时实测。保守上界过大并不能单独证明会超时，也不承诺所有同复杂度实现耗时相同。

**最后决定是否优化。**

- 最直接方案已安全覆盖完整范围时，它本身就是满分做法。可直接用 `## 满分做法：切割枚举 + 拼接搜索 + set 去重` 这类标题承载完整推导，不另贴一次“最简单做法”再重复为“满分做法”。
- 不够用时，指出具体耗时步骤及其可覆盖的原有部分分；每种部分分列出各步算法与成本、总时间和空间、完整代码。后续只改瓶颈或其必要关联步骤，说明改变后各步成本。
- 没有已知评分时不编造分值。有原公开分档时逐档说明；按第 4.3 节先核算直接算法的可得分档，共用程序合并讲解，不能把本可拿分的暴力省掉，也不能把满分程序伪称为低分程序。
- 只有一种满分做法时不编号。每种实质不同的算法都先逐步解析，再给总复杂度和完整代码；相同实现只完整出现一次，其他档次精确引用。主解与同目录 `std.cpp` 逐字一致，全部代码遵守第 3.5 节并抽取编译验证。
- 不固定添加“适用范围、核心观察、正确性证明、瓶颈与升级”等小标题；但正确性的关键依据、边界和优化成立条件必须解释。题解不出现材料核对、重构、验证日志或交付说明。

**逐步复杂度示例：切成 $k$ 段，再向两端拼接。** 设字符串长 $n$，合法切法数 $C=\binom{n-1}{k-1}$，生成次数 $P=C2^{k-1}$，不同结果数 $M\le P$。

1. 搜索 $k-1$ 个切点并生成各段：$C$ 种合法切法，每种处理 $O(n)$ 个字符，合计 $O(nC)$。
2. 对其余 $k-1$ 段枚举放前/放后：每种切法 $2^{k-1}$ 条路径，每条至多 $O(n)$ 字符处理，合计 $O(nP)$。
3. 将生成的字符串插入同一个 `set<string>`：每次比较至多 $O(n)$，集合规模至多 $M$，合计 $O(nP\log(M+1))$；存储结果占 $O(nM)$，还须计递归中保留的字符串。

总时间为 $O(nP\log(M+1))$；$P$ 是生成次数，不能误写成不同结果数，也不能把字符串插入成本写成 $O(\log n)$。

### 7.3 标题层级与版式

H1 是题号与题名；H2 用于“题意简化、问题拆分、最直接方案或实际采用的部分分/满分做法、知识点总结”；H3 默认用于“参考代码”，DP 可按需增加少量具体小标题。标题独占一行，H1/H2 后空一行、写独立的 `---`、再空一行进入正文。

PDF/HTML 保留真实标题字号、字重与段间距，并在 H1/H2 下渲染细横线；模板自带底线时合并重复线。标题和后面首段或代码开头保持同页。数学式和复杂度用 Markdown 数学标记 `$...$`，不要用反引号显示 `10^4` 等原始字符串；代码使用独立 `cpp` 围栏，伪代码标为 `text`。

简单方案已满分时，题解依次为：`# T? 题名` → `## 题意简化` → `## 问题拆分` → `## 满分做法：具体算法组合`（逐步规划、复杂度、代码）→ `## 知识点总结`。

需要优化时，在解法部分依次展开最直接方案及其部分分、必要中间做法、满分做法。标题直接表达做法与已有分值，不强制额外套一个“解法与程序规划”总标题，也不为了与模板对齐而写空章节。

### 7.4 整套题解与 PDF

完整包根目录 `solution.md` 只从最终 `T1/solution.md`～`TK/solution.md` 按题号整合，保留自足题意、编号步骤、逐步分档解析、代码和全部搜索/DP 图；图的编号、图例与叶子说明一并保留。不将根目录自身再次作为来源，不重写算法。相同代码在单题和汇总中必须一致。

同级 `solution.pdf` 由汇总 Markdown 生成，A4 竖版，每题从新页开始；目录、标题下横线、公式、代码与图均须逐页检查。搜索与 DP 图真正渲染为图，检查编号、左上角图例及虚线节点是否清楚，不能印成源码。修改单题后同步更新汇总，不增加单题 PDF 或图片目录。

### 7.5 搜索与 DP：先推导，图只画状态与编号边

DP 推导仍放在第 4 步的对应做法内部：**朴素搜索 → 合并等价子问题 → 状态拓扑图 → 记忆化或递推 → 必要优化**。先说明搜索参数、返回值、选择与停止条件，再用小例子解释状态复用，最后对应初始化、转移、答案和求值顺序。没有重复子问题就解释组合子结果，不虚构记忆化加速；同一状态与图在后续档引用，不重复三份等价程序。

凡题解把枚举决策的 DFS、回溯、BFS 状态搜索或记忆化搜索作为实际做法讲解，包括部分分和 DP 的朴素前身，均须画对应小实例搜索树/状态图。仅遍历已给定结构、没有选择分支的 DFS/BFS 不在此列。同一搜索被多档复用时画一次并明确引用，不能只给代码或文字。

每种实质不同的 DP 另给一张真实状态的小实例图，重复子问题应展示合流。不能用“搜索→DP”流程框代替，也不为画图发明 DP。两类图都按下列简图规则绘制。

#### 图的主体：状态节点＋编号边

- 节点内只写简短状态，如 `(i,c)`、`(3,2)`、`(l,r)`，不塞入状态定义、转移公式、代价、价值和解释段落。状态含义及初态在图前一句或左上角备注中说明一次；不逐节点写“正在处理……”或重复 F 值。
- 边保留清楚的箭头，边上只标决策编号。二选一默认 `0 = 不选`、`1 = 选`；多种选择用 `0,1,2,…`，枚举分割点等参数化选择可标 `k`、`j`，由图例定义。同一图中编号含义固定，不能时而指选择、时而指收益。
- 使用小实例或能看清关键分支、合流的局部图；不要为展示完整搜索过程画满指数级节点。状态按自然层次排列，避免大段说明框、套层容器、重复图例及装饰；拥挤时拆成少量相连小图，不缩小到难以阅读。
- 搜索图从真实实例初态画到合法终态；存在多种选择时展示至少两个分支，存在失败分支时展示虚线非法叶子。只画局部时标出未展开节点，不能用流程框冒充搜索树。
- 搜索树表示不同决策历史，允许出现相同状态；DP 图只合并后续子问题真正等价的状态，并保留不同决策的贡献。不能只因编号相似就合并，也不能因合并而漏掉计数重数。

#### 左上角集中备注：选择、条件、代价、价值

在图的左上方预留一个紧凑图例，不把图例当成状态节点接入图。每种决策只解释一次，格式为：

`编号 = 选择含义；条件：……；代价：……；价值：……`

例如状态 `(i,c)` 表示下一件物品为 i、剩余容量为 c：

```text
0 = 不选；条件：i ≤ n；代价：0；价值：0
1 = 选；条件：i ≤ n 且 c ≥ w[i]；代价：w[i]；价值：v[i]
```

- 图中对应边只标 `0` 或 `1`，不再重复“选择第 i 件物品／容量足够／收益为……”等句子。条件、代价与价值均通过编号查图例；状态变化由两端节点看出。
- 代价指本次资源消耗或目标成本，价值指本次产生的收益，不是运行时间或整个子问题值。无消耗或无收益写 `0`；随状态变化时用 `w[i]`、`v[i]` 等公式，不能把某条边的具体值当成全图常量。
- 计数、概率、可行性没有加法价值时，图例改标真实的系数、概率或逻辑贡献，不编造收益；不同决策如何合并在正文一句说明。图例不重复程序伪代码与完整递推式。

#### 图下统一标注叶子状态

- 图下用一两行写清：**合法叶子满足什么状态条件、返回什么；非法叶子满足什么条件、返回什么。** 节点内部仍只放状态，不给每个叶子重复一大段说明。
- 合法叶子用实线节点轮廓；非法或失败叶子用**虚线节点轮廓**，不能只把入边改虚线就算完成。虚线节点默认表示非法，不用同一画法表示未计算、重复状态或后续省略。
- 若需展示一个被条件禁止的尝试，用虚线箭头连到虚线失败节点，边上仍只标相应编号，并在图例注明虚线箭头不参与合法 DP 转移；无必要时直接不画这种尝试。沿合法选择到达但未满足最终目标的失败叶子，也使用虚线节点。
- 不强行制造不存在的非法叶子。局部图未展开的节点用实线轮廓，在其旁注明“后续省略”，不能假装成终态。
- 例如“恰好装满”的后向最值搜索，可在图下写：`合法：i = n+1 且 c = 0，返回 0；非法：i = n+1 且 c > 0，返回 −∞（虚线节点）`。若题目是“至多装满”，剩余容量大于 0 不代表失败；终态规则必须按题意确定。

#### 必要语义与核验保留，不堆进图里

- 在图旁或正文用一句话说明箭头和求值方向。默认箭头为搜索决策 `s → t`；若 F 表示剩余最优值，先算 t 再算 s；若 f 表示已取得的累计值，则顺拓扑更新。状态定义、边的即时贡献、初始化和代码不能混用；终态返回值不能一律写 0，未计算与无解也要区分。
- 区间／树形 DP 的一次决策若必须同时解决多个子问题，可增加最少量的合并节点，用简短符号标示，图例给出“全部合并”及组合公式；不能误画成任选一条路径。真实依赖有环且不能合法分层时说明原因，不伪造拓扑图。
- 图源优先内嵌于 `solution.md` 的 Mermaid 围栏，PDF 真正渲染并在左上角排好图例，不能只在源码中声称其位置正确。目标 Markdown 不支持图源时提供同文件文本兼容图或受支持的内嵌图形；正常渲染版本不重复显示兼容文本或图源，不依赖外链和散落图片。
- 图放在首次讲解对应搜索/DP 的 H2 内、参考代码之前；后续做法复用时指向该图，不用图例文字代替画图。
- 逐项用小实例核对状态、编号含义、条件、代价、价值、合法／非法叶子、合流与求值顺序；再检查节点内没有长段落、边上没有长句、图例只有一份、虚线确实画在非法节点上。正文不再逐字抄一遍图例。
- 单题、整套题解与 PDF 保持同一图义；图仅在教师题解中，临时图片不进入成品，不新增目录，也不放入题面、选手包、data.zip 或 attachment.zip。

**最终图形只包含：左上角小图例＋状态节点与编号边＋图下叶子条件。减少图内文字，不删除必要状态或改变算法语义。**

## 8. 最终交付结构

每套默认交付 `<套题名>_完整重构包.zip` 与 `<套题名>_选手下发包.zip`。`T?/` 表示实际存在的每道题；单题使用 `T1/`。以下目录树表示 ZIP 内部内容，不额外套一层同名包目录。

### 8.1 完整重构包：单题严格七项

```text
T1/ ... TK/
├─ statement.md
├─ statement.pdf
├─ std.cpp
├─ solution.md
├─ data/
│  ├─ 1.in
│  ├─ 1.out
│  └─ ...
├─ data.zip
└─ attachment.zip
solution.md
solution.pdf
题目汇总.pdf
```

- 每题根目录只有以上 6 个文件与 1 个 `data/` 目录；`solution.md` 含部分分与满分的逐步解析、代码，以及实际采用搜索/DP 的内嵌图源。图按第 7.5 节渲染进整套 PDF，不新增图片文件或目录。
- 不交付 `some.cpp`、`std_solution.md`、`some_solution.md`、单题 `solution.pdf`、`sample/`、`attachment/`，也不恢复 `docs/`、`judge/`、`release/`、`solutions/`。
- `data/` 与同级 `data.zip` 同时保留；公开附件只保留 `attachment.zip`。普通样例保留在题面中，不因删除样例目录而删除样例内容。
- 完整包根目录的整套 `solution.md`、`solution.pdf`、`题目汇总.pdf` 保持原要求；它们与各题内的同名文件按路径区分。
- 除用户授权的特殊判题例外外不增加文件。部分分临时源码、bf、alt、生成器、validator、wrong、变异程序、报告和缓存只留在内部工作目录。

### 8.2 data.zip 与 attachment.zip

```text
data.zip                 attachment.zip
├─ 1.in                  ├─ attachment1.in
├─ 1.out                 ├─ attachment1.out
├─ 2.in                  ├─ attachment2.in
├─ 2.out                 ├─ attachment2.out
└─ ...                   └─ ...
```

- `data.zip` 从最终 `data/` 生成，恰好包含 `1.in, 1.out, ..., P.in, P.out`，P 为正式点数；成员与目录文件名称、数量、逐文件 SHA-256 均相同。
- `attachment.zip` 从内部已验证的附件文件生成，恰好包含编号连续且成对的 `attachment1.in, attachment1.out, ...`；逐文件与内部来源核对并检验解压后的输入输出。源目录不交付。
- 两个 ZIP 的成员均直接位于 ZIP 根目录，无 `data/`、`attachment/`、`T1/` 等目录层级；不得夹带样例文件、题面、源码、题解、清单或其他压缩包。
- 拒绝重复成员名、绝对路径、`..` 路径、未配对文件和隐藏文件；全部内层 ZIP 做完整性检查。
- 数据或答案更新后重新生成相应 ZIP，不得保留旧压缩包。镜像只是交付形式，不增加正式测试点或公开附件数量。

### 8.3 选手下发包

```text
T1/ ... TK/
├─ statement.md
├─ statement.pdf
└─ attachment.zip
题目汇总.pdf
```

只从完整包逐项复制 `T?/statement.md`、`T?/statement.pdf`、`T?/attachment.zip` 和根目录 `题目汇总.pdf`，对应文件逐字节一致，包括 ZIP 本身；不重新生成选手版 PDF 或附件 ZIP。

选手包不得包含任何 `solution.md`、`solution.pdf`、`std.cpp`、其他源码、`data/`、`data.zip`、正式数据或内部信息。普通样例已经包含在题面中；公开附件 `.in/.out` 仅存在于 `attachment.zip` 内，不另交付散文件或目录。

### 8.4 双包与压缩包检查

- 完整包仅允许 `T?/data.zip`、`T?/attachment.zip` 两类内层 ZIP；选手包仅允许 `T?/attachment.zip`。内层 ZIP 内不能再有压缩包，两外层包不得互相嵌套。
- 两外层包分别从全新空目录按白名单组装；检查所有内外层 ZIP 完整性，以及正式数据目录与压缩版的一致性。
- 对选手包的外层路径和附件 ZIP 内的成员、内容一并做泄露检查，不能只按文件名判定公开性。
- 核对两个包的公开文件哈希一致；附件 ZIP 与内部验证源一致，不要求成品中存在已删除的 `attachment/` 或 `sample/`。

## 9. 最终验收门禁

完整交付时，只有下列项目全部通过才可标记 `PASS`；窄范围修复只验证受影响项目，不把未复核的整包标成 `PASS`。

### 题意与难度

- 题意唯一，约束、子任务、样例一致；
- 未经授权没有扩大范围、提高算法门槛或改变套题位置；
- 发现的更简单满分算法已正确处理，而非尝试卡掉。

### 算法与代码

- std 编译通过，并经暴力/独立方法验证；
- std 通过全部数据且性能、内存有合理余量；
- 各部分分代码对声明子域正确，已抽取编译并实测得分，异常通过或失败已如实处理；
- 所有完整 C++ 参考代码可编译并已验证；明确标注的搜索伪代码不冒充完整程序，也不计入编译数量；
- 最终代码通过基础语法、常见做法优先和删减式简化审计；
- 已知容量可用普通数组时不绕用动态容器；确需 `vector` 且大小已知时直接带长度构造，无多余 `resize`；每处复杂容器或语法都有必要性；
- 全部代码遵循第 3.5 节用户样例码风，粘贴噪声和无关模板已清理；不因模仿写法保留未初始化、越界、溢出或无用状态；
- 可自然递归的问题默认使用递归；显式栈模拟仅在第 3.4 节条件满足时出现，递归深度与实际栈环境已经验证；
- 同题 `std.cpp` 与 `solution.md` 主解代码逐字一致；部分分代码与已验证的内部抽取版本一致。

### 数据

- 测试点数量与总分正确；
- 先完成部分分和错误模型设计，后生成数据；
- 纯随机点不超过 20%，每点有明确职责；
- 适用的参数错位、复杂度退化、边界变异均被实际卡掉；
- 输入合法，输出经过独立确认；
- 样例、附件和正式数据互不重复。

### 题解与 PDF

- 简化题意可独立读懂输入结构、规模、操作、合法条件和目标；矩阵写明行列及元素含义，不以一句抽象目标代替题意；
- 问题拆分是编号步骤，每步有产物及下步用途；各做法沿用编号，不把读入输出当子问题；
- 最直接方案已完整规划，并核算各层方案数、调用次数、容器规模与单次操作成本；并列与嵌套复杂度没有混用，参数关系没有被忽略；
- 已代入完整范围判断可行性；朴素解足够时没有强凑优化，确实不足时才定位瓶颈和说明部分分；原公开分档未擅自改变；
- 已核算最直接算法在完整约束和原公开各档的可行性：它若已满分，不强设部分分；它若只能拿部分分，相应 H2 必须有编号步骤、逐步成本、总时空和完整可编译代码；共用程序合并讲解，不设无代码小节；
- 仅一种满分做法时不编号，多种做法才编号，不凑伪多解；
- 不套用固定的正确性、瓶颈与升级栏目，但必要的论证不能遗漏；知识点总结写清问题特征、使用前提和方法，不是泛泛的算法名列表；
- 实际采用的每种搜索均有真实小实例搜索图；DP 还另有状态合流图。搜索参数、分支、终态和 DP 状态复用、边界、求值顺序均已讲清；节点只写状态，边只标编号，左上角图例与代码一致；
- 图下已统一说明合法／非法叶子的状态条件与返回值；合法叶子实线、非法叶子虚线轮廓，省略节点不冒充终态；搜索方向、计算顺序及多子问题合并语义明确，不以流程框代替状态图、不伪造无环依赖；
- 所有必画的搜索/DP 图在单题与汇总中保留，PDF 已渲染；编号、图例、真实叶子和虚线失败节点清楚，Markdown 有可用图源；不以画图代替算法核验；
- H1/H2 真实分级且有标题下横线，正文与代码分开，PDF 逐页检查；
- 数学式与复杂度在 Markdown/PDF 中正确排版，未把 `10^4` 等幂次印成原始字符串；
- 题解无原材料、重构、版本变更或验证交付说明；
- 单题 `solution.md` 包含完整部分分与满分内容，未因文件合并遗漏做法或代码；根目录汇总与各题内容一致；主解与 `std.cpp` 一致。

### 双包与数据压缩

- 每题根目录严格为 statement.md、statement.pdf、std.cpp、solution.md、data/、data.zip、attachment.zip 七项；整套题解位于完整包根目录；
- 不出现已取消的分拆题解、独立部分分源码、sample/ 或 attachment/；普通样例仍在题面中且已验证；
- data/ 与 data.zip 成员及内容一致；attachment.zip 与内部验证源一致，解压后的附件已核验；
- 内层 ZIP 根目录直接为配对的输入输出文件，无多余外层目录；
- 完整包与选手包均符合白名单，所有外层、内层 ZIP 均可完整解压；
- 选手包及其 attachment.zip 均无正式数据、源代码、题解、搜索/DP 图或内部信息；
- 两包公开材料及 attachment.zip 逐字节一致；
- 无内部文件、缓存、非白名单 ZIP 或更深层压缩包。

状态含义：

- `PASS`：全部关键门禁通过；
- `NEEDS_FIX`：存在明确错误或高风险变异未卡掉；
- `RISK`：尚未发现错误，但验证或性能证据不足；
- `BLOCKED`：核心题意无法确定；
- `BLOCKED_SPECIAL_JUDGE`：必要判题组件与当前白名单冲突。
